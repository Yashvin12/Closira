# Database Migration Guide (Alembic)

This guide outlines the database migration workflow for Closira. Database schema changes are managed using **Alembic**, which interfaces with SQLAlchemy models to apply revisions systematically.

---

## 1. Setup & Configuration

Alembic configurations are specified in [alembic.ini](file:///c:/Users/Yashvin/OneDrive/Desktop/Closira/backend/alembic.ini) and the database URL is read dynamically from environmental variables inside [env.py](file:///c:/Users/Yashvin/OneDrive/Desktop/Closira/backend/alembic/env.py).

Make sure your virtual environment is active and the environment variables are set:

```bash
cd backend
source venv/Scripts/activate # On Windows: venv\Scripts\activate
```

---

## 2. Workflow for Schema Changes

When you need to modify the database schema (e.g., adding a new table, modifying a column, or adding an index):

### Step 1: Update SQLAlchemy Models
Modify the target ORM models. For example, to add a new field to users, open [user.py](file:///c:/Users/Yashvin/OneDrive/Desktop/Closira/backend/app/models/user.py) and update the model class definition.

### Step 2: Generate a Migration Script
Alembic can compare your current database schema against your SQLAlchemy definitions and autogenerate a migration script:

```bash
alembic revision --autogenerate -m "Add new field to users"
```

This creates a new Python migration file in `backend/alembic/versions/`.

### Step 3: Inspect the Autogenerated Migration
Always review the generated script in `backend/alembic/versions/` to verify it behaves correctly. Ensure the `upgrade()` and `downgrade()` methods perform the correct actions.

*Example structural inspection:*
```python
def upgrade() -> None:
    # Check that these matches your intention
    op.add_column('users', sa.Column('phone_number', sa.String(), nullable=True))

def downgrade() -> None:
    op.drop_column('users', 'phone_number')
```

### Step 4: Apply the Migration
Run the upgrade command to apply the changes to your local database instance:

```bash
alembic upgrade head
```

---

## 3. Common Commands Reference

| Action | Command |
|---|---|
| **Apply all pending migrations** | `alembic upgrade head` |
| **Rollback the last migration** | `alembic downgrade -1` |
| **Rollback to the beginning** | `alembic downgrade base` |
| **Check migration history** | `alembic history --verbose` |
| **Check current migration state** | `alembic current` |

---

## 4. Resolving Conflict / Branch Merges

If another developer merges a schema change while you are working on yours, Alembic may detect multiple heads. To merge them:

1. View the multiple heads:
   ```bash
   alembic heads
   ```
2. Create a merge revision to join the heads:
   ```bash
   alembic merge -m "Merge heads" <revision_id_1> <revision_id_2>
   ```
3. Apply the upgrade:
   ```bash
   alembic upgrade head
   ```
